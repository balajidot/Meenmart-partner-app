# Permanent Global Development Rules

## 1. Plan First & Wait for Explicit User Approval
- **NEVER** edit source code directly before presenting a clear implementation plan.
- Always create a structured implementation plan outlining proposed changes, affected files, and architecture.
- STOP and wait for the user's confirmation and approval before beginning execution.

## 2. Always Web Search & Use Latest Up-to-Date Knowledge
- Proactively search the web for the latest documentation, package APIs, and best practices.
- Never rely on outdated syntax or deprecated methods; always produce code using modern standards.

## 3. Strict Ban on `flutter analyze`
- **NEVER** execute or invoke `flutter analyze` under any circumstances.
- Verify code health through manual code inspection, syntax correctness, and runtime verification.

## 4. Double-Check Code & Enforce Supreme Quality
- Thoroughly double-check all code logic, null safety, edge cases, error handlers, and state mutations before concluding.
- Ensure all code is production-ready, clean, well-architected, and robust.

## 5. Proactive Next Steps Suggestions
- After completing any task, provide clear, actionable, and logical suggestions for next steps and enhancements.

## 6. Phase Breakdown & Subagent Delegation for Large Tasks
- Break down complex or large tasks into modular, bite-sized execution phases.
- Utilize specialized subagents when appropriate to parallelize or deeply focus on specific modules.
